# MVP Technical Design & Architecture

**Document Scope:** Detailed modular architecture, database schemas, API contracts, background job states, and worker responsibilities for the independent AI Video Clipping SaaS.

---

## 1. Modular System Architecture

To ensure we can add features (like new layouts, languages, or AI B-Roll) without rewrites, the system is strictly decoupled using a Redis event broker.

*   **API Service (Node.js/Express):** Handles HTTP, auth, Stripe, and enqueues jobs.
*   **Redis (BullMQ):** Maintains job state and retry logic.
*   **Worker 1 (Node.js - Ingestion):** Pulls streams via `yt-dlp`, validates with FFmpeg, uploads to R2, calls Deepgram API.
*   **Worker 2 (Python/Modal - LLM Curation):** Formats Deepgram transcript, prompts Claude 3.5, parses JSON response, saves candidate clips to DB.
*   **Worker 3 (Python/Modal - Vision & Reframe):** Downloads candidate clip segments, runs YOLOv8 face tracking, outputs JSON crop coordinates.
*   **Worker 4 (Node.js/Remotion - Render):** Takes crop coordinates, transcript words, and video URL, and renders final MP4s.

## 2. Database Schema (PostgreSQL)

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    credits INT DEFAULT 60,
    stripe_customer_id VARCHAR(255)
);

CREATE TABLE projects (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    source_url TEXT NOT NULL,
    raw_s3_key TEXT,
    duration_sec INT,
    status VARCHAR(50) DEFAULT 'PENDING', -- PENDING, PROCESSING, COMPLETED, FAILED
    error_message TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE transcripts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID REFERENCES projects(id) ON DELETE CASCADE,
    word_data JSONB NOT NULL -- [{word, start, end, speaker, conf}]
);

CREATE TABLE clips (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID REFERENCES projects(id) ON DELETE CASCADE,
    headline VARCHAR(255),
    start_time FLOAT NOT NULL,
    end_time FLOAT NOT NULL,
    score INT,
    score_reasons JSONB,
    crop_data JSONB, -- Generated by Vision worker
    render_s3_key TEXT,
    render_status VARCHAR(50) DEFAULT 'PENDING'
);
```

## 3. Background Job States (BullMQ)

The primary `video_processing_queue` follows a strict state machine payload updated at each step:

1.  **`DOWNLOADING`**: `yt-dlp` stream extraction.
2.  **`EXTRACTING_AUDIO`**: FFmpeg creates 16kHz mono WAV.
3.  **`TRANSCRIBING`**: Sent to Deepgram. Awaiting webhook/response.
4.  **`CURATING_HIGHLIGHTS`**: LLM is processing transcript blocks.
5.  **`TRACKING_FACES`**: Dispatching individual clip intervals to Modal GPU for bounding box tracking.
6.  **`READY`**: Clip objects are populated in DB. User can preview in UI.
7.  **`RENDERING`**: Remotion/FFmpeg is generating the hardcoded MP4s.
8.  **`COMPLETED`**: Video URLs available to user.

## 4. Internal API Contracts

### 4.1 Internal API: Start Vision Tracking (To Modal)
*   **Endpoint:** `POST https://modal-app-id.modal.run/track_faces`
*   **Payload:**
    ```json
    {
      "video_url": "https://r2.bucket.com/raw.mp4",
      "start_time": 142.15,
      "end_time": 194.80,
      "aspect_ratio": "9:16"
    }
    ```
*   **Response:**
    ```json
    {
      "crop_trajectory": [
        {"t": 142.15, "x": 420, "y": 0, "w": 1080, "h": 1920},
        ...
      ]
    }
    ```

### 4.2 Web UI API: Get Project Status
*   **Endpoint:** `GET /api/projects/:id`
*   **Response:**
    ```json
    {
      "id": "proj_123",
      "status": "TRACKING_FACES",
      "progress_percent": 65,
      "clips": []
    }
    ```
